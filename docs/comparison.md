[^1]: `sqlite3 database.sqlite` writes into the working directory, and a new named volume takes the owner of the directory it is mounted on. `keinos/sqlite3` and `cleanstart/sqlite3` run their user in `/`, which root owns, so both fail with `unable to open database file`.

[^2]: sqlite.org lists [these options](https://sqlite.org/compile.html#recommended_compile_time_options) "for applications that are able to use them" to save CPU cycles and memory, and to turn off legacy misfeatures. `SQLITE_THREADSAFE=0` alone makes SQLite about 2% faster and smaller.

[^3]: A static binary carries its own libc and needs nothing from the OS, so the same binary runs on every Linux distribution and there are no shared libraries to keep patched.

[^4]: PID 1 ignores signals it has no handler for, so without an init `docker stop` waits out its grace period and then kills the container.

[^5]: `load_extension()` lets any SQL that reaches the shell run native code from a file.

[^6]: linux/arm64 where published, linux/amd64 otherwise.

[^7]: JSON is built into SQLite since 3.38.0 and therefore not listed. A distribution package ships the extensions the distribution chose, which is why the Red Hat build has fewer than the amalgamation offers.
