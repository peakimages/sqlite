[^1]: `sqlite3 database.sqlite` writes into the working directory, and a new named volume takes the owner of the directory it is mounted on. `keinos/sqlite3` and `cleanstart/sqlite3` run their user in `/`, which root owns, so both fail with `unable to open database file`.

[^2]: Building the same commit again gives the same image byte for byte, so a rebuild shows whether a published image really comes from its source. The image manifest of each platform keeps its digest, while the digest of a tag changes with every build because the provenance attestation records the build run.

[^3]: sqlite.org lists [these options](https://sqlite.org/compile.html#recommended_compile_time_options) "for applications that are able to use them" to save CPU cycles and memory, and to turn off legacy misfeatures. `SQLITE_THREADSAFE=0` alone makes SQLite about 2% faster and smaller.

[^4]: A static binary carries its own libc and needs nothing from the OS, so the same binary runs on any Linux distribution and there are no shared libraries to keep patched.

[^5]: A position-independent executable is loaded at a random memory address on every start, so an exploit cannot rely on known memory addresses.

[^6]: Most of the other images run the interactive `sqlite3` shell as their main process, which exits when its input ends. With `docker run -d` or as a Compose service, the container stops with exit code 0 unless `-i` or `-t` (`stdin_open` or `tty` in Compose) is set. A running container allows database health checks, scheduled tasks, backups and debugging through its shell.

[^7]: PID 1 ignores signals it has no handler for, so without an init, `docker stop` waits out its grace period and then kills the container.

[^8]: `load_extension()` lets any SQL that reaches the shell run native code from a file.

[^9]: Measured for `linux/amd64`.

[^10]: `grepular/sqlite3` packs its binary with UPX, which unpacks it into memory on every start: every `sqlite3` run, a health check too, starts about 200 times slower (25 ms instead of 0.1 ms on arm64), every process keeps its own unpacked copy in memory instead of sharing one, and antivirus scanners may flag the file, as malware often uses UPX. It pays on every start to save on size, on a download that happens once.

[^11]: JSON has been built into SQLite since 3.38.0 and is not listed. A distribution package ships the extensions its distribution chose, and SQLite before 3.35.0 has no math functions.
